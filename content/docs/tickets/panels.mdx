title: Ticket panels

A panel is a message with a dropdown or a row of buttons. Each option is a
[category](/docs/tickets/categories), and clicking one opens a ticket.

You can build panels in the dashboard or with commands. The dashboard is easier and
does more; the commands work on every plan.

## Building one in the dashboard

**[bravenbot.com/dashboard](https://bravenbot.com/dashboard) → your server → Ticket
panels → Customise**

Four tabs, with a live Discord preview beside them that updates as you type.

### Appearance

Everything about how the embed looks:

| Setting | Notes |
| --- | --- |
| **Panel name** | Internal only. Members never see it — it is how you find the panel in the list. |
| **Channel** | Where the panel is posted. |
| **Title** and **Description** | The embed's heading and body. |
| **Colour** | Or leave it to inherit your [server branding](/docs/account/branding). |
| **Message above the embed** | Plain text posted alongside. Mentions here never ping — a panel that re-pinged `@everyone` every time you edited it would be a problem. |
| **Author**, **Footer**, **Image**, **Thumbnail** | Standard Discord embed parts. |
| **Show timestamp** | Adds the posted time to the footer. |

### Options

**Dropdown** holds up to 25 categories behind one menu. **Buttons** put each category
on the message itself — better for three or four, unwieldy past that.

The options themselves are edited here too. Click one to open it, and use the arrows
to change the order members see. Each option can override the panel it sits on:

| Setting | What it does |
| --- | --- |
| **Label**, **Description**, **Emoji** | What members read. Descriptions only show on dropdown panels. |
| **Button colour** | Buttons panels only. |
| **Opening message** | The first message in the ticket. Blank uses the default. |
| **Staff roles** | Handle this option only. Blank falls back to the panel's support roles — which is how one panel can send reports to one team and refunds to another. |
| **Ticket channel** | Where this option's tickets open. Blank uses your server's ticket channel. |
| **Open tickets per member** | `0` inherits the panel's limit. Set it here to cap this option on its own. |

Options save one at a time, with their own **Save option** button — separate from the
panel's Save. Editing an option never changes its ID, so a panel you posted a year ago
keeps working after you rename it.

### Behaviour

Who handles these tickets and how they behave:

- **Support roles** — who can see and claim tickets from this panel. Falls back to
  your server's staff roles when empty, so a panel with nothing set still works.
- **Viewer roles** — pinged when a ticket opens so they can read it, without being
  the team on the hook for answering it.
- **Ask before closing** — a confirmation step on the close button. On by default.
  Turn it off if your staff close a lot of trivial tickets and the extra click is
  friction rather than a safety net.
- **Keep closed tickets** — a closed ticket is locked but stays where it is, with
  **Reopen** and **Delete ticket** buttons on it, instead of being archived. Nobody
  can keep talking in it; staff can still read it and pick it back up.
- **Pin the first message** — pins the opening message in each ticket.
- **Open tickets per member** — stops one person opening fifteen. `0` means no panel
  limit; your plan's overall ticket limit still applies and cannot be raised here.
- **Ticket number padding** — `4` shows ticket 57 as `0057`.
- **Open ticket name** and **Closed ticket name** — rename the thread using
  `{counter}`, `{member.name}` and `{guild.name}`. Blank uses the built-in
  `support-0001` scheme. Anything Braven does not recognise is left as you typed it.
- **Staff-only thread** — opens a second private thread beside each ticket for staff
  to talk in. The person who opened the ticket is never in it.
- **Roles while a ticket is open** — added to the opener when their ticket opens and
  taken back when it closes. Braven reverses exactly what it did, so changing this
  setting never strips a role from someone whose ticket predates the change.

<Callout type="warn">
Renaming a thread is rate limited by Discord to twice every ten minutes. On a busy
server the closed-ticket rename can be skipped — the ticket still closes.
</Callout>

### Embed fields

Up to 25 name-and-value pairs inside the embed. Useful for "what to include in your
report" without making the description enormous.

## Posting and editing

**Post** puts the panel in the channel. It is queued rather than instant — the
dashboard hands it to the bot, which picks it up within about fifteen seconds.

After that, **Save edits the message already in Discord.** You do not repost, and the
panel does not move or lose its place in the channel.

<Callout title="Editing a panel never breaks it">
  Braven's buttons carry no hidden state — they reference a category, and the
  category is looked up when somebody clicks. So you can rewrite a panel as often as
  you like, and one posted a year ago still works. This is also why Braven survives
  updates without the "This interaction failed" problem other ticket bots have.
</Callout>

**Duplicate** copies a panel, its categories and its fields into a new unposted panel
— the fastest way to make a second panel that is mostly like the first.

**Delete** archives it. The message stays in Discord and keeps working; it just
disappears from your dashboard. Nothing already opened is affected.

## Doing it with commands

```
/panel create channel:#support title:Support
/panel category panel:1 label:General Support
/panel post panel:1
```

`/panel create` prints the panel's ID, which the other two need. And:

```
/ticketconfig style panel:1 style:buttons
```

## Limits

| Plan | Panels | Categories |
| --- | --- | --- |
| Free | 1 | 3 |
| Pro | 5 | 15 |
| Elite | Unlimited | Unlimited |

Discord caps any single panel at 25 options regardless of plan.

If you downgrade, nothing is deleted. Panels over the limit stay exactly as they are
and keep working — you simply cannot create another until you are back under it.
